Check for fresh docs without downloading them again.

304 reuses text · 200 replaces it · offline falls back to cache

0:30-0:31. Conditional GET

SAY (key points, in your own words)

  • Narrative docs come from llms-full.txt, about 7.7 MB.
  • The CLI sends the ETag it saved last time in If-None-Match.
  • 304 means nothing changed: serve the copy on disk. 200 means new docs: store the new ETag and text.
  • If the network fails, it falls back to the cached copy, so docs search works offline.

0:31-0:32. Two caches, one fingerprint

SAY (key points, in your own words)

  • Each read checks memory first, then disk. A disk hit gets promoted into memory.
  • Files are written to a temp file, then moved into place, so a crash never leaves half a cache.
  • The parsed index is saved with a fingerprint: XxHash3 of the schema version plus the text.
  • Same docs and same schema: skip the parse. Change the parser, bump the schema version, and every machine re-parses on its next run.

Where a word matched. How rare it is.

A title hit outweighs body text. A rare term like addredis outweighs azure, which is on nearly every page. No embeddings, no model training.

0:33-0:34. How search ranks

SAY (key points, in your own words)

  • Two numbers decide the rank: where a word matched, and how rare it is.
  • Titles, summaries, headings and code carry more weight than body text.
  • IDF means inverse document frequency: it counts how many documents contain a token, not how often it repeats on one page. This BM25-style formula gives rare terms a larger multiplier; it is one ingredient in the ranking, not full BM25.
  • Rarity is an IDF multiplier: azure is on almost every page, addredis is not.
  • No embeddings, no model training: when you ask for a method, you mean that method.
